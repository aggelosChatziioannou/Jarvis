# Custom "Hey Jarvis" Wake Word — Design

**Date:** 2026-05-29
**Status:** Approved by user (Angelos / "Boss"); ready for implementation planning.
**Goal:** Build the best "Hey Jarvis" wake detection the user's hardware can support — trained with the user's own recordings plus synthetic + augmented data — so the user no longer has to lean into the mic or repeat the phrase, and detection is as robust as physically possible at mid-range.

## Plain-language summary

Today Jarvis uses the stock **openWakeWord** `hey_jarvis_v0.1` model, which is a **speaker-independent phrase detector** (it listens for the words, not for a specific person). The user has to sit close to the mic and often repeat "Hey Jarvis" 2-3 times before it triggers. We will train a **custom openWakeWord model** tuned to the user's voice, mic, and room, and tune the detection path, to maximise robustness.

## Honest constraints (calibrated with the user)

- openWakeWord is **speaker-independent**. The user's recordings make the model **robust** (to their accent, mic, room), they do **not** make it "only them" or magically extend range. (openWakeWord's optional *verifier* is the only place per-speaker data restricts triggering, and it is explicitly out of scope here because it tightens, not widens, detection.)
- The **PD200X is a dynamic cardioid podcast mic** — engineered for lips-on-the-grille speech and to reject distant/off-axis sound. **Reliable 2-3 m is beyond its physical design.** Realistic outcome of this project: noticeably more robust, likely reliable to ~1-1.5 m. True 2-3 m would need a far-field mic / array (explicitly a separate, later, optional project).
- Detection range is governed by **mic + gain + threshold + model robustness** — addressed by Steps 0-3 below.

## Approach: record + synthetic + augmentation → custom model

### Step 0 — Baseline tuning (free, do first; also the measurement baseline)
- Lower `wispr_wake_threshold` from the current `0.5` toward `~0.3` (config default in code is `0.1`).
- Add a software **wake gain** (`wispr_wake_gain`, default `1.0`) applied to the wake audio *before* the openWakeWord detector, so a weak/distant signal is amplified into the detector's useful range (clipped safely). Gain is applied ONLY to the wake-detection copy of the audio, never to the dictation/transcript path.
- Guidance to raise the Windows mic level / boost on the PD200X.
- Captures a **before** detection-rate baseline so the custom model's improvement is measurable, not assumed.

### Component 1 — In-app guided recorder (the user's data)
- A small, guided recorder (CLI command and/or a Settings panel action) that prompts the user to say "Hey Jarvis" ~15-25× at each of **0.3 / 1 / 2 / 3 m** and a couple of off-axis angles, plus a handful of **negatives** (the user's normal speech, room noise, silence).
- Saves **16 kHz mono WAV** clips, labelled by distance/angle, under a known data dir (e.g. `~/.local/share/jarvis/wakeword/positives/<distance>/...`, `.../negatives/...`).
- Captures the user's voice + the **PD200X's actual far-field response** + the user's room acoustics — the data the stock model never had.
- Privacy-first: recordings stay local; never uploaded except (optionally, by the user's explicit action) to the chosen training environment.

### Component 2 — Offline training → model artifact
- openWakeWord training pipeline: the user's recordings as **positives**, plus **synthetic** "Hey Jarvis" generated by Piper across many voices, plus **negatives** (speech/noise corpora), plus **augmentation** — room impulse responses (reverb), background noise, and low-volume/distance simulation — so the model tolerates a weak, reverberant signal.
- **Training environment:** recommended **Colab notebook** (openWakeWord's official path; zero local setup, sidesteps the user's Blackwell RTX 5070 Ti CUDA/training-stack friction). Local training on the 5070 Ti remains an option if the training deps are confirmed to support Blackwell during the research step. The user records locally either way.
- Output: a custom model file (`.onnx`/`.tflite`) placed under the openWakeWord models dir.

### Component 3 — Integration + evaluation
- Place the trained model under the models dir; point `wispr_wake_model` at it; keep the tuned threshold + gain.
- The recorder **doubles as an evaluation harness**: replay the distance-labelled clips through the detector (stock vs custom, before vs after tuning) and report **detection rate per distance** + false-trigger rate on the negatives. This turns "feels better" into a real number.

## Files (anticipated; finalised in the plan)
- `src/jarvis/listening/wispr_bridge.py` — apply `wispr_wake_gain` to the wake audio; honour `wispr_wake_model` for a custom model path; (threshold already configurable).
- `src/jarvis/config.py` — new keys: `wispr_wake_gain` (float, default 1.0); confirm `wispr_wake_model` / `wispr_wake_threshold` plumbing.
- New: a recorder module + CLI entry (e.g. `src/jarvis/listening/wakeword_recorder.py`) and/or a Settings panel action.
- New: an eval harness (replay clips → detection-rate report).
- New: offline training assets/notebook + a short README (kept out of the runtime path).
- Specs: a `*.spec.md` next to the recorder/integration code once built; update `docs/llm_contexts.md` only if an LLM context changes (none expected — openWakeWord is not an LLM).

## Testing
- Unit: `wispr_wake_gain` scales the wake audio (and clips safely) without touching the transcript path; config keys load/round-trip; the recorder writes correctly-formatted 16 kHz mono WAVs to the right labelled paths; custom-model path resolution + fail-open to the stock model when the custom model is missing.
- Eval: detection-rate harness over the labelled clips (stock vs custom), reported per distance; false-trigger count over negatives.
- Manual: the user records, trains, drops in the model, and confirms improved triggering at arm's length / ~1 m.

## Out of scope
- Far-field hardware (mic array / sensitive condenser) for true 2-3 m — a separate optional project.
- A per-speaker verifier ("only me") — tightens detection, opposite of the goal; can be revisited if false triggers become a problem.
- Changing the dictation/transcription path (Wispr Flow) — untouched.

## Key decisions
- Custom model over stock, trained on record + synthetic + augmentation (user's choice).
- Train in Colab by default (least friction on Blackwell); local optional.
- Step-0 tuning is a prerequisite + baseline, not an alternative.
- Honest range target: robust to ~1-1.5 m on the PD200X; 2-3 m deferred to hardware.
